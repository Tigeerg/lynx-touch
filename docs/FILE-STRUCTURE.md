# FILE-STRUCTURE.md — структура проекта, артефакты и временные файлы

Документ о том, **где что лежит**, что считается исходником, что — собранным артефактом, а что —
временным мусором. Правила действуют для всех агентов и людей; проверяются сторожем
(`tools/check.ps1`) и скриптом уборки `scripts/clean.ps1`.

## 1. Что показал аудит (01.11.2026)

| Место | Объём | Что это | Решение |
|---|---:|---|---|
| `build/` | ~0,63 ГБ, 5018 файлов | собранные Qt/C++ программы, пробники, Qt/OCCT DLL | оставить поддеревья, убрать мусор из корня |
| `apps/react-interface/.next` | ~320 МБ | кэш Next.js | не хранить, чистится |
| `build/cpp` | 2 DLL | старый мост `gvbridge`/`gvqtshim` | удалить как устаревшее |
| корень `build/` | ~30 файлов | наши скриншоты, одноразовые `.mjs`/`.ps1`, логи, тестовые `.ngc` | удалить, правило ниже |
| `img/` | 7 PNG (tracked) | принятые скриншоты для README/приёмки | оставить, проверять ссылки |
| `ZIP/` | 10 МБ | локальный архив, ignored | не источник истины, в коммит не идёт |
| tracked `build/` | 0 файлов | — | так и держать |

Вывод: мусор — не сами собранные программы, а **одноразовые файлы, положенные в корень `build/`**.
Их место — `build/artifacts/` (временное) или `img/` (принятое), а не рядом с exe.

## 2. Дерево проекта

```
apps/
  react-interface/      исходники панели (Next.js, TypeScript), testdata/
  qt-interface/         исходники Qt-порта (QML, C++), tests/, panel-data.js
  quickprog/            C++-демо CAM (исходники, tests/)
modules/
  gcode-viewer/         3D-вьювер: QML, cpp/, testdata, oracle_manifest.json
data/
  cad-testdata/         тестовые УП/модели, постпроцессор
docs/                   планы, архитектура, этот документ
img/                    ТОЛЬКО принятые скриншоты (tracked)
scripts/                сборка/запуск/уборка, по одному смыслу на скрипт
tools/                  сторож и общие проверки
build/                  сгенерированное, ignored (см. §3)
```

Корень — только документы проекта (`README`, `CLAUDE`, `AGENTS`, `VERSION`, `projects.json` и
т.п.) и лицензия. Исходники — в `apps/`, `modules/`, `data/`, `docs/`, `scripts/`, `tools/`,
`img/`.

## 3. `build/`: сгенерированное, не исходники

`build/` целиком в `.gitignore`; **ни один файл оттуда не коммитится**. Внутри — подкаталоги по
проектам:

| Каталог | Что внутри | Кто создаёт |
|---|---|---|
| `build/edges` | gvcore, STEP/STL, пробники, CNC.Edges | `scripts/build-viewer.ps1` |
| `build/viewer` | `gcodeviewer.exe`, `keyprobe`, `stock_bind_probe`, Qt/OCCT | `scripts/build-viewer.ps1` |
| `build/qmlbackend` | MockBackend | `scripts/build-viewer.ps1` |
| `build/quickprog` | `quickprog.exe`, `quickprog_check.exe` | `scripts/build-quickprog.ps1` |
| `build/qt-interface` | `lynx-panel.exe`, Qt/OCCT | `scripts/build-qt-interface.ps1` |
| `build/artifacts` | временные скриншоты, логи, пробные файлы | агент/человек |
| `build/tmp` | одноразовые скрипты и выгрузки | агент/человек |
| `build/logs` | логи прогонов | агент/человек |

Правила:

1. **В корне `build/` — только подкаталоги.** Никаких `*.png`, `*.qml`, `*.mjs`, `*.ps1`,
   `*.log`, `*.txt`, `qp-*.ngc` прямо в `build/`.
2. **Одноразовое — в `build/tmp/`, логи — в `build/logs/`, скриншоты — в
   `build/artifacts/screenshots/`.** Всё это удаляется без сожаления.
3. **Полная уборка** — `scripts/clean.ps1 -Build` (удаляет `build/` целиком; потом пересборка).
4. **Частичная уборка** — `scripts/clean.ps1 -Artifacts` (корень `build/`, `build/artifacts`,
   `build/tmp`, `build/logs`, старый `build/cpp`).
5. **Кэш Next.js** (`apps/react-interface/.next`) не хранится; чистится `-Next`.

## 4. Скриншоты и доказательства

* **Принятое — только в `img/`** (tracked). Один файл — одно состояние, по которому была приёмка.
* **Рабочее/черновое — только в `build/artifacts/screenshots/`** (ignored), удаляется уборкой.
* Имя: `<область>_<что>_<дата>[_<состояние>].png`, латиницей, например
  `viewer_solid.png`, `panel_softkeys_fit.png`, `qt_work_2026-11-01.png`.
* В `img/` не кладут промежуточные кадры «на всякий случай», дубли и кадры с чужим UI.
* Ссылка на скриншот в документации обязательна; файл без ссылки — кандидат на удаление.
* Перед релизом `img/` пересматривают: устаревшие кадры удаляют вместе с ссылками.

## 5. Временные скрипты и выгрузки

* **Многоразовый скрипт** → `scripts/` (Windows `.ps1`, при необходимости Linux `.sh`), с
  шапкой: назначение, запуск, код возврата. Только тогда он коммитится.
* **Одноразовый** (проверить гипотезу, снять кадр, сравнить файлы) → `build/tmp/` или системный
  `%TEMP%\opencode\`; в репозиторий не попадает.
* **Тестовые выгрузки** (`.ngc`, `.qprog`, `.png`, логи) → `build/artifacts/`, не в `testdata/`.
* `testdata/` — только эталоны, на которые ссылаются тесты; временные файлы там запрещены.

## 6. Архивы и сторонние файлы

* `ZIP/` — локальный склад архивов, ignored; не источник истины и не место для правок.
* Релизные архивы — `dist/` (ignored), не в корне и не в `build/`.
* Скачанные SDK (Qt, OCCT) — вне репозитория (`C:\Qt`, `D:\cnc-toolchain`); в проекте только
  переменные `CNC_QT_DIR`, `CNC_OCC_DIR`.
* Бинарники (`*.exe`, `*.dll`, `*.pdb`, `*.lib`) в репозитории не хранятся (кроме тестовых
  данных, если появятся осознанно и с записью в `TODO.md`).

## 7. Уборка

```powershell
# показать, что занимает место и что будет удалено (ничего не трогает)
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/clean.ps1

# убрать одноразовые файлы и старые каталоги, сборки оставить
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/clean.ps1 -Artifacts

# убрать build/ целиком (потом пересобрать) и кэш Next.js
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/clean.ps1 -Build -Next
```

Уборка **никогда** не удаляет `apps/`, `modules/`, `docs/`, `img/`, `data/`, `scripts/`, `tools/`
и корневые документы. Если путь не входит в белый список `build/`/`.next`, скрипт отказывает.

## 8. Проверки сторожа

`tools/check.ps1` дополнительно проверяет:

1. в git нет отслеживаемых файлов из `build/` и `.next/`;
2. в git нет `*.exe`, `*.dll`, `*.pdb`, `*.lib`, `*.obj`;
3. в корне `build/` нет файлов — только каталоги;
4. в корне репозитория нет `*.png` (скриншоты — только `img/` или `build/artifacts/`).

Нарушение — `FAIL` с путём, а не предупреждение: иначе мусор возвращается.

## 9. Когда убирать

* после каждой принятой волны — `-Artifacts`;
* перед релизом — `-Artifacts -Next` и просмотр `img/`;
* при смене SDK/сборки — `-Build` и полная пересборка;
* перед коммитом — `git status --ignored` глазами: в коммит не должно попасть ничего из
  `build/`.
