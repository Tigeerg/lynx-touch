# PANEL-BACKEND.md — контракт данных панели и симулятор

Запись этапа 0 переноса панели на Qt: у интерфейса появляется один контракт данных
(`MachineBackend`), симулятор для тестов и демонстрации и стенд сравнения снимков. Экраны пока
читают свои значения из `main.qml`; этап 0 не переключает их на контракт, а готовит почву, чтобы
это переключение было механическим и проверяемым.

Термины: словарь для человека — [`ROLES.md`](../ROLES.md), раздел 9; в тексте термин расшифрован
при первом употреблении (`AI_WORKFLOW.md`, раздел 0.2).

## 1. Зачем контракт

Сейчас числа и тексты станка зашиты в `apps/qt-interface/main.qml`. Пока источник данных — сам
файл панели, подключить LinuxCNC нельзя: некуда вставить чтение HAL-пинов, а тест не отличит
живое значение от литерала.

Контракт решает три задачи:

* **Один шов.** QML знает только свойства и команды `MachineBackend`; откуда пришли значения —
  симулятор или станок — панель не спрашивает и не ветвится.
* **Честный отказ.** Команда возвращает `{ ok, reason }`; отказ показывается оператору строкой,
  а не молчанием. Нет `if (simulator)` внутри экранов.
* **Повторяемость.** Симулятор читает JSON-фикстуру и может заморозить часы, поэтому снимок
  панели одинаков от прогона к прогону.

## 2. Где лежит

| Файл | Роль |
|---|---|
| `apps/qt-interface/backend/machine_types.h/.cpp` | Типы данных: позиция, инструмент, смещение, сообщение, программа, коррекции; `toMap()` — только граница QML |
| `apps/qt-interface/backend/machine_backend.h/.cpp` | Публичный контракт: свойства, команды, сигналы; отказ по умолчанию — «Backend не подключён» |
| `apps/qt-interface/backend/sim_state.h` | Полное состояние симулятора |
| `apps/qt-interface/backend/fixture_reader.h/.cpp` | Чтение и проверка JSON-фикстуры; битая фикстура не затирает прежнее состояние |
| `apps/qt-interface/backend/sim_backend.h/.cpp` | Симулятор: те же запреты (занятость, авария, режим), шаги JOG, коррекции, MDI |
| `apps/qt-interface/backend/backend_factory.h/.cpp` | Выбор backend по имени: `sim` или `linuxcnc` |
| `apps/qt-interface/backend/fixtures/*.json` | Состояния для тестов и снимков |
| `apps/qt-interface/backend/tests/tst_backend.cpp` | 12 проверок контракта и симулятора |
| `apps/qt-interface/BackendBridge.qml` | Шов панели: значения на чтение, команды назад, `lastReason` (§4) |
| `apps/qt-interface/tests/StubBackend.qml` | Заглушка backend для QML-тестов: те же свойства и команды |

`lynx-backend` — статическая библиотека без Qt Quick: её можно проверить без окна. `lynx-panel`
и `lynx-backend-test` линкуются с ней.

## 3. Контракт

Свойства только для чтения (сигнал — в скобках):

* состояние: `backendName`, `connected`, `lastError`, `run` (`IDLE`/`RUN`/`HOLD`/`ALARM`/`ESTOP`),
  `mode` (`AUTO`/`MDI`/`JOG`/`MPG`), `workplace` (`SETUP`/`TEST`/`RUN`);
* геометрия: `position`, `machinePosition`, `offsets`, `activeOffset`;
* инструмент: `tools`, `tool`, `toolTime`, `probe`;
* программа: `programs`, `program` (активный файл, строка, курсор, следующая строка);
* станок: `overrides`, `spindle`, `coolant`, `load`, `axisLoad`, `rapidSteps`;
* счётчики: `cycleTime`, `lastCycle`, `partCount`;
* прочее: `alarms`, `singleBlock`, `optStop`, `dryRun`, `message`, `clock`, `focused`, `mdiHistory`.

Команды (`Q_INVOKABLE`, все возвращают `{ ok, reason }`): `cycleStart`, `feedHold`, `reset`,
`emergencyStop`, `setWorkplace`, `setMode`, `jog(axis, step, direction)`, `mdi(text)`,
`loadProgram(index)`, `startFromCursor`, `setOverride(kind, direction)`, `toggle(key)`,
`acknowledgeAlarms`, `clearAcknowledgedAlarms`.

Правила симулятора повторяют React-редьюсер, а не выдумывают своё:

* смена рабочего места и режима запрещена, пока программа выполняется или на паузе;
* JOG доступен только в `JOG`/`MPG`, шаги — 0.001 / 0.01 / 0.1 мм;
* коррекция подачи и шпинделя — 0…150 % шагом 10, быстрых — ряд 5/25/50/100;
* авария и `ALARM` требуют сброса до любой команды;
* MDI понимает `G90`/`G91`, `M3`/`M4`/`M5`, `M8`/`M9` и координаты `X/Y/Z/A`; история — три
  последние команды.

## 4. Шов панели (`BackendBridge.qml`)

Экраны не знают, какой backend за контрактом. Между ними и `MachineBackend` стоит один объект
`BackendBridge.qml`:

* **Значения на чтение.** `backend.run`, `position`, `tool`, `programName`, `overrides`,
  `activeAlarmCount`, `clock` и остальные — панель и сенсор берут числа и подписи только отсюда;
  подписи (`runLabel` — «ГОТОВ»/«ВЫПОЛНЕНИЕ»/…, `toolLabel` — `T01`, `activeOffsetCode`) собирает
  шов, а не каждый экран.
* **Команды назад.** `backend.cycleStart()`, `feedHold()`, `reset()`, `emergencyStop()`,
  `setWorkplace()`, `setMode()`, `jog()`, `mdi()`, `setOverride()`, `toggle()` и прочие вызывают
  станок и возвращают `true`/`false`.
* **Отказ виден.** Причина отказа ложится в `backend.lastReason`; экран показывает её строкой
  сообщения. Без backend причина — «Backend не подключён».
* **Нет ветки «симулятор или станок».** Панель не спрашивает, кто за швом; выбор делает
  `--backend` в `main.cpp`.

Подключено на этом шаге: состояние прогона, имя и титул УП, счётчик сообщений и часы в шапке
(панель и сенсор); команды цикла, шпинделя и СОЖ; смена рабочего места и режима; позиция (DRO
панели и сенсора), джог, MDI-строка, «в ноль детали», «отвод в безопасную точку» и коррекции
подачи/шпинделя/быстрых.

Ещё локально (переезжает следующими срезами, см. §8): каталог УП и редактор, таблицы смещений,
инструмента и сообщений, обмер инструмента, мастер щупа, лестница, сервисные параметры и счётчики
деталей (у контракта пока нет команды счётчика).

## 5. Выбор backend и запуск

```
lynx-panel.exe --backend=sim --fixture=apps/qt-interface/backend/fixtures/auto-idle.json
lynx-panel.exe --backend=linuxcnc   # ошибка: адаптер ещё не написан
```

* `--backend` по умолчанию `sim`; `linuxcnc` завершает запуск с внятным сообщением. Тихого
  отката на симулятор нет: панель на станке не должна показывать вымышленные числа. Панель —
  GUI-процесс, поэтому при запуске из консоли она заново подключается к ней и печатает причину
  отказа; код возврата — 1.
* `--fixture` — путь к JSON (относительный считается от корня репозитория).
* `--freeze-clock=HH:mm:ss` — заморозить часы для повторяемого снимка.
* `--screen`, `--workplace`, `--theme` — стартовое состояние для отладки и снимков.
* `--shot=file.png` и `--shot-delay=ms` — снять панель в PNG и выйти. Режим снимка загружает
  `main.qml` напрямую (без `panel-host.qml`), чтобы состояние успело примениться до кадра; окно
  подстраивается под холст панели (1024×600 или 864×1536), а снимается сам холст. Заодно снимок
  подставляет в шапку часы из замороженного состояния backend — иначе кадр ловил бы бегущую
  секунду.

Фикстуры: `auto-idle.json` — АВТО, полный набор инструмента, смещений и сообщений;
`setup-probe.json` — НАЛАДКА с щупом; `test-dry.json` — ПРОГОН с холостым ходом.

## 6. Стенд сравнения

| Инструмент | Что делает |
|---|---|
| `tools/panel-shot.ps1` | Offscreen-снимок панели: фикстура, экран, рабочее место, тема; кладёт PNG в `build/artifacts/screenshots/` |
| `tools/panel-diff.ps1` | Сравнивает эталон и снимок с допуском на канал, пишет красную маску расхождений и падает при превышении бюджета |

Сравнение — не «побайтно равно»: Chromium и Qt по-разному растеризуют текст. Допуск по каналу
(`-Tolerance`, по умолчанию 8) и доля расхождений (`-MaxDiff`, по умолчанию 0.5 %) задают
границу «пиксельного паритета»: геометрия и цвета совпадают, сглаживание шрифта может отличаться.

```
powershell -NoProfile -ExecutionPolicy Bypass -File tools/panel-shot.ps1 `
    -Out build/artifacts/screenshots/auto-idle.png -Fixture auto-idle -Screen prog -Theme 0
powershell -NoProfile -ExecutionPolicy Bypass -File tools/panel-diff.ps1 `
    -Reference img/react/auto-idle.png -Actual build/artifacts/screenshots/auto-idle.png `
    -Diff build/artifacts/screenshots/auto-idle.diff.png
```

Скрипты пишутся в UTF-8 с BOM: Windows PowerShell 5.1 без BOM читает кириллицу как ANSI и
разбирает строку с тире как незакрытую кавычку.

## 8. Что ещё не сделано

* Экраны читают `machine` через шов: шапка (состояние прогона, УП, счётчик сообщений, часы),
  позиция (DRO), джог, MDI-строка, безопасная точка, ноль детали и коррекции — уже живые.
  Остальное — каталог УП и редактор, таблицы смещений/инструмента/сообщений, обмер, щуп, лестница,
  сервис, счётчик деталей — ещё локально и переезжает по одному экрану.
* Нет `LinuxCncBackend`: адаптер к HAL/`linuxcnc` появится после этапа 1; до него
  `--backend=linuxcnc` намеренно падает.
* Темы «Минимал» в Qt нет: `--theme` принимает 0…5, но палитр пока четыре.
* Симулятор не проигрывает траекторию вьювера: он двигает координаты по кадрам УП, но не
  синхронизирует их с 3D-сценой.
