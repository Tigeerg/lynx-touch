# Симуляция съёма материала: план работ

Рабочий документ, а не описание сделанного. Источник истины для текущего кода -
`cpp/core/stock_sim.{h,cpp}`, `stocksurface.vert/frag`, `qmlbackend/gv_stockgeom.*`,
`qmlbackend/gv_toolpath.*` и раздел «Симуляция съёма материала» в `DESIGN.md`. Числа
здесь либо взяты из замеров (с указанием откуда), либо названы предложением.

Порядок: сначала точная отрисовка (этап 1) на текущем поле, затем математически
быстрый и точный расчёт поля (этап 2). Общие правила - `CLAUDE.md` (русский язык
комментариев, `->` вместо глифа стрелки, единицы в именах) и `VERSIONING.md`
(порядок правки, проверки, версии).

## 1. Что есть сейчас

- Представление: карта высот nx x ny по машинным X/Y, в узле глубина от верха
  заготовки (float32 -> R32F). Индекс узла `iy * nx + ix`.
- Съём: `StockField::plunge` в одном положении, `StockField::sweep` идёт по
  3D-длине отрезка шагом `cellMm * 0.5`, поле берёт `max` глубины (то есть `min`
  высоты). Режет нижняя огибающая профиля `h(r)` до вылета; оправка не режет.
- Профиль: `StockCutter` - радиальная таблица `h(r)` с линейной интерполяцией;
  шар набран 12 хордами, угловая фаска - 8.
- Поднутрение (`LOLLIPOP`, `DOVETAIL`, `T_SLOT`/`TSLOT`, а также профиль шире
  кверху): обход отказывается целиком, поля нет вовсе.
- Живой обход: `StockWalk` хранит поле и курсор, продолжает с последнего целого
  хода, назад по пути - сброс и обход с начала.
- Отрисовка: вершина на узел, два треугольника на ячейку, вся сетка; высоту
  вычитает вершинный шейдер выборкой nearest; нормаль - центральная разность через
  `NORMAL_SPAN = 2` текселя; цвет - порог `cutMm = 0.05` по `vDepth`.
- Публикация: копия всего поля в `QByteArray` на рабочем потоке, целая загрузка
  `QQuick3DTextureData` раз в 100 мс (частичной загрузки у неё нет).

Замеры `Test_model.ngc` (70 914 ходов, 137,8 м, габарит `UI_STOCK` 150x100 мм),
`cpp/core/quality.h:70-78`:

| узел | узлов | цена | поле | треугольников (сетка) |
|------|-------|------|------|------------------------|
| 0,5 мм | 301x201 = 60 501 | 192,4-425 мс | 236 КиБ | около 120 000 |
| 0,2 мм | 751x501 = 376 251 | 2288,6-8393 мс | 1,44 МиБ | около 750 000 |

Потолок по `DESIGN.md` - до 2 093 000 треугольников (узел 0,2, потолок сетки 1024).

## 2. Где теряются точность и время

1. Повторный обход узла. Узел на траектории покрыт примерно `4r / узел` соседними
   положениями одного хода (при `r = 3`, узел 0,2 -> до 120 раз), и каждое
   положение заново считает `sqrt`, `heightAt` и `max`. Главный множитель расхода.
2. Дискретизация хода. Шаг `cell / 2` - приближение огибающей: снаружи радиуса
   остаётся необработанная полоса шириной до `cell / 4`. Случай `flat_sweep` в
   `stock_sim_probe` эту полосу вынужденно исключает из сверки.
3. Хорды вместо дуг. Сагитта 12 хорд шара - 0,00835 мм (`stock_sim_probe`, случай
   `ball_plunge`); дуга фаски грубее.
4. Полная сетка. Память, треугольники и загрузка текстуры считаются по всему
   прямоугольнику заготовки, хотя тронута тонкая полоса или карман.
5. Ступени в отрисовке. Кусочно-постоянная высота, нормаль через 2 текселя,
   бинарный цвет по nearest: мозаика и зубцы; `NORMAL_SPAN` - компромисс между
   наклоном кромки и потерей мелких окон (`stocksurface.vert`).
6. `DESIGN.md` обещает кадровые замеры поля (frame-строки `bench_probe`), но в
   `cpp/bench_probe.cpp` их нет - бюджет кадра поля не измеряется вовсе.

## 3. Новый метод

Поверхность собирается из слоёв с точной границей реза, а съём считается как
точная огибающая каждого хода по капсуле, а не выборкой положений. Хранение - те
же узлы, но разреженные (тайлы), рядом с глубиной - маска «тронуто».

### 3.1 Отрисовка

- Слоистая поверхность вместо одной выдавленной сетки: верх (плоскость `zMax` там,
  где не тронуто), дно реза (карта высот) и вертикальная стенка по точному контуру
  границы реза.
- Точный контур - marching squares: глубина на границе линейно пересекает ноль,
  под-ячейковое положение перехода даёт полилинию, из неё - вертикальные квады.
  Стенка кармана становится ровной линией, без ступеней.
- Непрерывная реконструкция высоты в шейдере (руками из 4-16 текселей, не
  фильтром: линейная выборка R32F на ветке OpenGL 3.3 не гарантирована). Нормаль
  считается во фрагменте (Sobel или аналитика), `NORMAL_SPAN` уходит.
- Адаптивный меш (restricted quadtree): ячейка дробится только там, где глубина
  меняется быстрее допуска; соседи различаются не больше чем на уровень, T-стыки
  сшиваются. Цена кадра - периметр резов, а не площадь заготовки.
- Тайлы вместо одной текстуры: свой `QQuick3DTextureData` и свой `Model` на тайл
  (например, 64x64 узла). Тик грузит только грязные тайлы; нетронутый тайл не
  рисуется и не грузится.
- Антиалиасинг границы по знаковому расстоянию до контура (в стиле существующего
  distance-field AA лент), без MSAA.

### 3.2 Расчёт

- Точная огибающая хода. Ход `A -> B`, инструмент `h(r)`. Для узла `P`:
  `H(P) = min по t из [0,1] от ( z(t) + h(r(t)) )`, где `z(t) = zA + (zB - zA) * t`,
  `r(t)` - расстояние от `P` до точки отрезка в XY. Тронуты только узлы с
  `min_t r(t) <= maxRadius`, то есть капсула (отрезок плюс диск); обходится ровно её
  bbox, каждый узел - один раз на ход.
- Замкнутая форма вместо итераций. `h(r)` - нижняя огибающая, неубывающая,
  кусочно-линейная. На куске `h = a + b * r` (`b >= 0`) функция
  `f(t) = z(t) + b * r(t)` выпукла (r(t) выпукла, b >= 0). Критическая точка:
  `t = t* - dz * d / ( sqrt(L2) * sqrt(b * b * L2 - dz * dz) )` при `b * b * L2 > dz * dz`,
  иначе минимум на конце; здесь `t*` - проекция `P` на прямую хода, `d` - расстояние
  от `P` до прямой, `L2 = |B - A|^2`, `dz = zB - zA`. Клэмпим к под-интервалу куска
  (где `r(t)` в `[r_i, r_i+1]`) и к `[0,1]`; берём минимум из кандидата и концов.
  Для дуг (сфера, фаска) `h` неубывающая и выпуклая, выпуклость `f` сохраняется -
  минимум защищённым Ньютоном с фиксированным числом шагов (детерминированно).
  Итог без ошибки дискретизации: уходят и полоса `cell / 4`, и зависимость от шага.
- Аналитический профиль: примитивы (отрезок, дуга, тор) рядом с существующей
  таблицей; истинная сфера и фаска вместо многоугольника.
- Разреженные тайлы: нетронутый тайл неявен (глубина 0), память и цена - по
  площади и периметру реза. Детерминизм сохраняется: `max` глубины точен и не
  зависит от порядка обхода, поэтому побитовые дайджесты пробников осмысленны.
- Живой обход: курсор `StockWalk` остаётся, инкремент идёт по грязным тайлам.
  Перемотка - через журнал вкладов: съём монотонен, на тайл хранится вклад
  (индекс хода, значение), перемотка есть бинарный поиск и `max` по вкладам
  (O(1) на узел вместо полного пересчёта префикса, что сейчас стоит 200-232 мс, а
  на узле 0,2 - до 4 с по `DESIGN.md`). Базовая версия - пересчёт по грязным тайлам,
  журнал - отдельным шагом.
- Поднутрение (опция): вместо отказа - усечённый дексель, до `k` слоёв на колонку
  только в этапах с поднутрением. `k = 1` - текущая карта, `k = бесконечность` -
  дексель из `DESIGN.md` §13; цена платится лишь там, где нужна.
- GPU (опция, позже): ходы в SSBO, gather-min по капсуле во фрагменте для больших
  программ; на ветке OpenGL 3.3 и слабом железе - после CPU-версии.

Оценка выигрыша (порядок, не замер): устранение повторного обхода даёт около
`4r / узел` (10x при `r = 1,5`, узел 0,5; до 120x при `r = 3`, узел 0,2);
разреженность добавляет выигрыш по доле тронутой площади.

## 5. Риски и что отвергаем

- Ветка OpenGL 3.3: линейная фильтрация R32F не гарантирована - реконструкция
  руками; тайловые текстуры проверяются прототипом до кода (замер, как требует
  `DESIGN.md`).
- Тайлы против одной текстуры: больше объектов сцены; порог - по замеру кадра.
- Marching squares даёт границу по линейной интерполяции: при узле 0,5 мм это много
  точнее узла, но не абсолютная дуга; при необходимости - кривые второго порядка на
  ячейку.
- Отвергаем сейчас: полный voxel/SDF-raymarch (память и OpenGL 3.3), CSG-булевы на
  GPU (непереносимо на слабом железе), дексель по умолчанию (дорог, `DESIGN.md` §13).
- Детерминизм: точный метод меняет байты поля, но дайджесты пробников сравнивают
  прогоны между собой, а не с хранимым эталоном, поэтому `oracle_manifest.json` не
  ломается; влияние отмечается в `CHANGELOG.md` явно.
