# tools/checks.txt - shared run list of the guard. It is executed by tools/check.sh
# (Linux, bash) and the same list drives the list in tools/check.ps1 (Windows,
# pnpm guard). A line is one check:
#
#   label|requirement|command
#
# Requirements: probe - built probes needed (build/edges); plugin - the built
# MockBackend QML module needed (build/qmlbackend/MockBackend/qmldir) and the
# entry point build/viewer/gcodeviewer - without them not a single viewer run
# starts; frame - frame capture (same build as plugin).
#
# The executor calls commands from the repository root with QT_QPA_PLATFORM=offscreen
# and counts a check red if the return code is non-zero or the output contains a
# Traceback or a line starting with WARNING/ or ERROR/: the return code alone
# is not enough, a crash inside the run does not change it. Requirement not met -
# the check is printed as skip.
#
# There is no Python layer in the repository: the probes compare against the
# reference themselves (key --manifest, array digests against
# modules/gcode-viewer/oracle_manifest.json), field analytics of the stock removal -
# by stock_sim_probe cases, live paths - by viewer/* probes. Measurements
# (bench_probe, stock_sim_probe phases) are not part of the list: they
# print numbers, not a verdict.
#
# The text rules of CLAUDE.md, file size labels, pnpm/React runs and the C++
# build under MSVC stay in tools/check.ps1: they need Windows or node.
