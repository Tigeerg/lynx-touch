# tools/checks.txt - общий список прогонов сторожа. Его исполняет tools/check.sh
# (Linux, bash) и по нему же правится список в tools/check.ps1 (Windows,
# pnpm guard). Строка - одна проверка:
#
#   метка|требование|команда
#
# Требования: probe - нужны собранные пробники (build/edges); plugin - нужен
# собранный QML-модуль MockBackend (build/qmlbackend/MockBackend/qmldir) и точка
# входа build/viewer/gcodeviewer - без них не стартует ни один прогон вьювера;
# frame - съёмка кадра (та же сборка, что у plugin).
#
# Исполнитель зовёт команды из корня репозитория с QT_QPA_PLATFORM=offscreen и
# считает проверку красной, если код возврата не нулевой или в выводе есть
# Traceback либо строка, начинающаяся с WARNING/ или ERROR/: одного кода
# возврата мало, падение внутри прогона его не меняет. Требование не закрыто -
# проверка печатается как skip.
#
# Питоновского слоя в репозитории нет: пробники сверяются с эталоном сами (ключ
# --manifest, дайджесты массивов против modules/gcode-viewer/oracle_manifest.json),
# аналитика поля съёма - случаями stock_sim_probe, живые пути - пробниками
# viewer/*. Замеры (bench_probe, фазы stock_sim_probe) в список не входят: они
# печатают числа, а не вердикт.
#
# Текстовые правила CLAUDE.md, метки размеров файлов, pnpm-прогоны React и сборка
# C++ под MSVC остаются в tools/check.ps1: им нужен Windows или node.
