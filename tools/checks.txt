# tools/checks.txt - общий список прогонов сторожа. Его исполняют tools/check.sh
# (Linux, bash) и tools/check.ps1 (Windows, pnpm guard). Строка - одна проверка:
#
#   метка|требование|команда
#
# Требования: python - нужен интерпретатор; ocp - нужен пакет cadquery-ocp
# (импорт OCP, см. requirements-dev.txt); plugin - нужен собранный QML-плагин
# MockBackend (build/qmlbackend/MockBackend/qmldir); live - живая проверка
# кадра: нужен эталонный стенд (аппаратный GL и живое окно, offscreen отдаёт
# чёрный кадр), пороги откалиброваны под него. live исполняется только при
# CNC_LIVE_FRAMES=1 в окружении, иначе печатается как skip с этой причиной.
#
# Исполнитель зовёт команды из корня репозитория с QT_QPA_PLATFORM=offscreen и
# считает проверку красной, если код возврата не нулевой или в выводе есть
# Traceback либо строка, начинающаяся с WARNING/ или ERROR/: одного кода
# возврата мало, падение внутри прогона его не меняет (тот же приём, что в
# tools/check.ps1). Требование не закрыто - проверка печатается как skip.
#
# Текстовые правила CLAUDE.md, метки размеров файлов, сверка preview.qml с
# генератором, pnpm-прогоны React и сборка C++ под MSVC остаются в
# tools/check.ps1: им нужен Windows или node.
#
# У bench_viewer.py вторым аргументом идёт потолок, мс: сторож даёт 20 - в пять
# раз выше потолка машины-эталона (4.0 мс), чтобы ловить катастрофический
# регресс интерактивных фаз, а не разброс машин.
